# arguelles.me

A static personal site generated by a small Python + Jinja2 engine. Content lives in
Markdown and JSON; HTML lives in Jinja templates; CSS and JavaScript are separate,
lintable files. The output is plain static assets deployed as a Cloudflare Worker.

## Quick start

```bash
cd src
npm ci
npm run build          # builds ./dist
npm run dev            # builds, then serves ./dist on http://127.0.0.1:4321
```

Python dependencies are installed automatically into `src/.venv` by `scripts/build.sh`
(using `uv` when available, otherwise `venv` + `pip`).

## Content and templates

- Blog posts are Markdown with YAML front matter (`title`, `description`, `pubDate`,
  `tags`, optional `image`, optional `draft`).
- Custom fenced components (`mermaid`, `timeline`) are documented in
  [`docs/markdown-components.md`](docs/markdown-components.md).
- `content/tools.json` is the source of truth for the tools index. A local tool also
  needs `templates/tools/<slug>.html` and, unless it is a PyScript tool,
  `assets/js/tools/<slug>.ts`.
- Templates use `templates/partials/macros.html` for icons, badges, tags, buttons, and
  panels. Shared markup belongs in a macro or partial, not copy-pasted.
- There are no inline `<script>` or `<style>` blocks. CSS lives in `assets/css/` and
  JavaScript in `assets/js/`; the build rejects inline scripts, inline styles, inline
  event handlers, and `style=` attributes in generated HTML.

## Tool pages

- JavaScript tools: a Jinja template in `templates/tools/`, an entrypoint in
  `assets/js/tools/<slug>.ts`, and optional page CSS in `assets/css/tools/<slug>.css`.
  esbuild bundles each entrypoint to `dist/assets/js/tools/<slug>.js`.
- Python tools: a Jinja template that loads the shared `py-tools.ts` and a
  `<script type="py" src="/tools/<name>/main.py" config="/tools/<name>/config.json">`.
  The Python source and config live in `static/tools/<name>/`.
- Third-party browser libraries are vendored from pinned npm dependencies. They are
  copied into `dist/assets/vendor/` at build time, so Renovate can bump them and there
  is no runtime CDN script dependency for those libraries.

PyScript itself is vendored from `@pyscript/core`, and the pure-Python plotly wheel is
downloaded from the pinned `requirements-vendor.txt` and served same-origin. PyScript
still loads the Pyodide runtime and its built-in packages from the upstream CDN at
runtime. The CSP in `static/_headers` restricts where it can load from; PyScript needs
`script-src 'unsafe-eval'` and `'wasm-unsafe-eval'`.

## Deployment

This is a Cloudflare **Workers** static-assets project, not Cloudflare Pages.

- Workers Builds root directory: `src`
- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- `src/wrangler.toml` points `assets.directory` at `./dist` and serves `404.html` for
  missing paths.

The build is self-contained: `npm run build` installs Python dependencies, compiles
TypeScript, vendors libraries, renders every route, copies static assets, and validates
the output.

## Checks

```bash
cd src
ruff check .
npm run typecheck
python -m pytest -q
npm test
python build.py
```

The build itself fails if it emits an inline script, inline style, inline event handler,
or a broken internal link.

## Dependencies and Renovate

`renovate.json` enables the recommended managers for npm, pip, and GitHub Actions.
`src/package.json` pins exact versions for esbuild, Vitest, TypeScript, and every vendored
browser library. `src/requirements.txt` pins the Python engine dependencies. `src/requirements-vendor.txt`
pins the plotly wheel that is downloaded into `dist/assets/python/` at build time.
