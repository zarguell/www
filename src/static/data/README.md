# Baked eBird data

`ebird-taxonomy.json` and `ebird-names.json` are generated by
`scripts/build-taxonomy.py`. Do not edit them by hand.

| Field | Contents |
|---|---|
| `f` | `[common name, scientific family name]` per family, index into `m` |
| `o` | order names, index into `m` |
| `m` | species binomial -> `[family index, order index, body mass in grams]` |
| `s` | state/province code (`US-MD`) -> display name |
| `c` | country code (`US`) -> display name |

`ebird-names.json` is a flat binomial -> common name map, fetched only when a share
link is opened. A full export carries the name on every row, so the shared view is
the only one that has to look it up; keeping it separate saves ~90 KB gzipped on the
taxonomy every visitor fetches.

## Sources and credits

- **Taxonomy:** eBird/Clements checklist via `api.ebird.org/v2/ref/taxonomy/ebird`
  (keyless reference endpoint).
- **Body masses and region names:** [Everybird](https://github.com/yusuftaleb/everybird)
  by Yusuf Taleb (MIT). Everybird sources masses from
  [AVONET](https://doi.org/10.1111/ele.13898) (CC BY 4.0) and
  [BIRDBASE](https://doi.org/10.1038/s41597-025-05615-3) (CC BY 4.0), and region names
  from Natural Earth (public domain) and Debian iso-codes (LGPL-2.1, names only).
- **Stickers:** [huashu-bird-sticker](https://github.com/alchaincyf/huashu-bird-sticker)
  by Huashu, CC BY 4.0. Loaded from jsDelivr at runtime, not committed here.

Regenerate after a taxonomy change (eBird updates theirs every August):

```bash
python scripts/build-taxonomy.py          # rewrite
python scripts/build-taxonomy.py --check  # fail if stale
```
