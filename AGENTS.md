# AGENTS.md

Single source of truth for agents working on this repository.

## What this is

A static site for `www.arguelles.me`, generated by a Python + Jinja2 engine. Markdown and
JSON content goes in, static HTML comes out. The site is deployed as a **Cloudflare
Worker with static assets** (not Cloudflare Pages).

## Quick start

```bash
cd src
npm ci
npm run build     # builds ./dist
npm run dev       # builds and serves on http://127.0.0.1:4321
```

## Architecture

| Layer | Location |
|-------|----------|
| Engine | `src/engine/` and `src/build.py` |
| Content | `src/content/` (`site.json`, pages, blog, links, tools) |
| HTML | `src/templates/` (Jinja2) |
| CSS | `src/assets/css/` (split, concatenated to `main.css`) |
| JavaScript | `src/assets/js/` (TypeScript, esbuild-compiled) |
| Static passthrough | `src/static/` |
| Tests | `src/tests/` (pytest) and `src/tests/js/` (Vitest) |
| Deployment | `src/wrangler.toml` |

## Hard rules

- **No inline HTML/script/style in output.** No inline `<script>`, no inline `<style>`,
  no `onclick=`/`on*=` attributes, no `style=` attributes. The build validates this.
  Styles go in `assets/css/`; behavior goes in `assets/js/`.
- **No CDN scripts.** Vendor browser libraries from pinned npm dependencies. The engine
  copies them to `dist/assets/vendor/`; `build.py` owns the mapping. The only exception
  is PyScript's own Pyodide runtime loading, which is constrained by CSP.
- **Keep the engine boring.** Prefer small functions with type hints and docstrings over
  framework-style abstraction.
- **Reuse patterns.** Shared markup belongs in `templates/partials/macros.html` or a
  partial. Shared CSS belongs in `assets/css/components.css` or `tools.css`. Do not
  introduce a second convention.
- **Content is data.** Do not hardcode blog posts, links, or tool registry entries in
  templates. Put them in `content/`.
- **Every local tool needs all three pieces:** a template, a JS entrypoint (or the shared
  PyScript entrypoint), and a registry entry in `content/tools.json`.

## Agent files

`engine/pages.py::build_llms` generates `/llms.txt` plus Markdown versions at
`/index.md`, `/about/index.md`, `/links/index.md`, `/blog/index.md`, and
`/blog/<slug>/index.md`. Keep those links crawlable and absolute. Do not add
interactive tools to the agent index. HTML pages emit the matching
`rel="alternate" type="text/markdown"` and `rel="describedby"` links.

## Custom Markdown components

The build supports fenced `mermaid` and `timeline` blocks. Read
`docs/markdown-components.md` before adding or changing one. The parser lives in
`engine/render.py`; component CSS lives in `assets/css/prose.css`; behavior lives
in `assets/js/`.

## Adding a blog post

1. Add `src/content/blog/<slug>.md` with YAML front matter:
   `title`, `description`, `pubDate`, optional `pubTime`, `tags`, optional `image`,
   optional `draft`.
2. Run the build. The index and RSS are generated automatically.

## Adding a tool

1. Add the entry to `src/content/tools.json` (with a `slug` for local tools).
2. Add `src/templates/tools/<slug>.html` extending `tool.html`.
3. Add `src/assets/js/tools/<slug>.ts` unless it is a PyScript tool. PyScript tools use
   the shared `py-tools.ts` and a `<script type="py" ...>` tag.
4. Add page-specific CSS in `src/assets/css/tools/<slug>.css` if needed.
5. Add or update tests when the tool has non-DOM logic.

## Build verification

A green exit code is not proof. Before pushing:

```bash
cd src
rm -rf dist
python build.py
test -f dist/index.html
test -f dist/tools/index.html
```

Then serve `dist/` and check the page you changed in a browser. The engine's validator
already checks inline-code violations and broken internal references.

## Checks

```bash
cd src
ruff check .
npm run typecheck
python -m pytest -q
npm test
```

## Deployment

Workers Builds settings:

- Root directory: `src`
- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`

`src/wrangler.toml` owns asset routing and the 404 fallback. Do not convert this repo to
Cloudflare Pages.
